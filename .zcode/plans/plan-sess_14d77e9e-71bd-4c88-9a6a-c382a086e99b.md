# 五项功能开发计划（云栖 PMS）

## Context

在已交付的多店酒店 PMS（FastAPI + React）上新增 5 项前台高频功能：①入住放宽房态限制 ②日历一键设净 ③钟点房 ④自定义延住 ⑤预订级操作日志查看。完成后进行 code review。

**未收到答复、按推荐执行的三个假设**（如不符请指出）：
1. 直接落码，不改 design/prototype 原型（本批以行为逻辑为主，视觉全部复用现有设计系统类）
2. 钟点房按 **小时单价** 计价：房型配置「钟点价/小时」，开单选时长，账目 = 时长 × 单价
3. 延住价格口径为 **每晚单价**（默认带出当前房价，可改），账目追加「延住房费 · N 晚 × ¥单价」

## 功能 1：入住不检查脏房 / 前客未退

**后端**
- `backend/app/routers/reservations.py` check-in（L293-294）：删除 `vacant_clean` 强制校验，改为仅拦截 `maintenance`（维修房仍不可入住）；`blocking_ids` 调用改为只按 pending/confirmed 计冲突（`deps.py` 的 `blocking_ids`/`free_rooms` 加 `allow_prev_guest` 参数，checked_in 不再阻挡入住——即前客未退也可入住）。入住 summary 在房态为 occupied 时追加「（前客未退）」
- `backend/app/routers/rooms.py` `/api/rooms/available`：加查询参数 `include_dirty=1`、`allow_prev_guest=1`（默认不变，向后兼容）
- check-out 增加一致性护栏：退房时若该房还有**其他** checked_in 预订（功能 1 造成的同房双客），跳过「房态转空脏 + 清洁任务」，日志注明
- `backend/app/routers/rooms.py` patch_room：房态改为 vacant_clean 时，自动把该房 pending/in_progress 清洁任务置为 done（避免脏房被手动设净后残留幽灵任务）

**前端**
- `frontend/src/dialogs.tsx` CheckInDialog：available 请求带新参数；选房格对非空净房显示「未清洁 / 前客未退」角标；空态与 lockedNotReady 文案同步改

## 功能 2：日历已退房房间一键设净

## 功能 3：钟点房

**模型 + 迁移**
- `backend/app/models.py`：`RoomType.hourly_price`（元/小时，0=不支持）；`Reservation.stay_type`（normal/hourly）、`Reservation.hours`
- `backend/app/db.py` 加 `run_sqlite_migrations()`（create_all 之后执行：PRAGMA table_info 检查缺列 → ALTER TABLE ADD COLUMN），在 `main.py` lifespan 调用——现有 pms.db 无迁移机制，必须补列
- `backend/app/seed.py`：大床房/双床房配钟点价（如 45/55 元/小时）

**后端**
- `reservations.py` create_reservation：`ReservationBody` 加 `stay_type`/`hours`；hourly 时强制 `check_out = check_in + 1 天`（占用整天，冲突判断复用现有半开区间）、hours 校验 1–12、rate 默认取房型 hourly_price（未配置且未传价 → 400）；房费账目 `钟点房费 · N 小时 × ¥单价`
- `ReservationOut` 加 stay_type/hours；board 接口 block 加 stay_type/hours、房间行加 hourly_price

**前端**
- `Rooms.tsx` BookDialog：房型支持钟点时显示「整晚 / 钟点」切换 + 时长选择（默认 4 小时），汇总行显示预估金额（需把 group 的 room_type_id 传入，修 `toRoom` 丢类型 id 的问题）
- `Reservations.tsx` NewReservationDialog：同样加整晚/钟点切换
- 日历 block：hourly 显示「钟点 · N小时」标签（复用 `.cal-block` 加类）
- `api.ts` 类型同步（RoomType/Reservation/CalBlock/BoardRoom）

## 功能 4：延住自定义天数 + 价格

- **新端点** `POST /api/reservations/{id}/extend`（`reservations.py`）：仅 checked_in；body `{nights=1, hours=0, rate=None}`；普通预订 check_out +N 天（冲突按 pending/confirmed 计，409）、价格默认 `r.rate`；钟点预订按小时延长（r.hours 累加，离店日不变）；追加 FolioItem `room_charge`「延住房费 · N 晚 × ¥价」，不动原房费行；写 `reservation_extend` 日志
- 前端：`dialogs.tsx` 新增共享 `ExtendDialog`（天数默认 1、单价默认当前房价，预览新离店日/金额）；`Rooms.tsx` 详情弹层「延住一天」直调替换为弹窗；`FrontDesk.tsx` 在住列表「延住」按钮同样接弹窗
- 已知边界（代码注释注明，review 重点）：延住产生增量账目后，若再拖动改期，PATCH 仍只重算首条房费行，可能重复计费

## 功能 5：预订操作日志查看

- **新端点** `GET /api/reservations/{id}/logs`：按 `object_id == res_id AND object_type IN ('reservation','payment')` 查（payment 日志的 object_id 存的是预订 id），倒序返回 `{time, action, summary, operator}`
- `Rooms.tsx` 预订详情弹层底部加「操作日志 ▾」展开区（懒加载，复用 `.info-row`/`.badge`，新增 `.oplog-list` 滚动样式）
- `Reports.tsx` 的 action→中文映射抽到 `api.ts` 共享（`OP_ACTION_LABEL`，新增 `reservation_extend: 延住`），两处复用
